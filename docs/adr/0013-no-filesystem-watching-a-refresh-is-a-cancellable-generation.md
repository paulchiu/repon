# No filesystem watching; a refresh is a cancellable generation

Repon watches no filesystem. A cheap sweep of `HEAD`, `index`, `packed-refs` and `refs/` runs on a short interval instead, and its blindness is stated rather than engineered around: it sees a commit, a checkout, a stage and a hard reset, and misses an unstaged edit, an untracked file and a fetch. Watching is closed rather than deferred. A watch cheap enough to arm can only see values that are already free to recompute, and the value that would justify a watcher needs the working tree watched, which is where the entry count is. The corollary is that a watcher crate must never enter the dependency tree.

A refresh is a Generation, and an abandoned Generation is cancelled rather than left to finish, because two Generations contending for the same cores make the second pay for both. Cancellation is cooperative, so late results still arrive and must still lose: every result carries the Generation that produced it, and the comparison happens at the point of writing the cell rather than at the channel, which makes supersession per entity rather than global. The deadline belongs to the Generation, not the cell, because a rayon task cannot be pre-empted and a per-cell deadline would only mark a cell while the work carried on underneath it.

**Enforcement:** `dirty_counts_passes_its_own_cancel_flag_to_should_interrupt_owned` in `crates/repon/src/test_support.rs` reads `dirty_counts`'s marked region in `crates/repon-core/src/git.rs` and fails if the cancellation flag or gix's per-repository thread limit ever leaves it; `probe_fan_out_still_uses_rayons_global_pool_rather_than_a_dedicated_one` holds the fan-out's other half. `a_lower_generation_write_does_not_overwrite_a_higher_one` in `crates/repon-core/src/cell.rs` holds write-time supersession. `no_filesystem_watcher_and_no_runtime_theme_command_exist_anywhere_in_either_crate` in `crates/repon/src/app.rs` scans both crates' manifests and source for a watcher crate or its call shapes, and `just check-core-isolation` keeps one out of the core's dependency tree.
