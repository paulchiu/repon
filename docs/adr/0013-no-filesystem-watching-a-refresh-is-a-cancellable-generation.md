# No filesystem watching; a refresh is a cancellable generation

A real watcher was built and run rather than reasoned about: notify 8.2.0 with notify-debouncer-mini 0.7.0, recursive over both roots. It costs nothing to speak of. FSEvents delivers over a Mach port, so the file descriptor delta is zero regardless of tree size, resident memory rises by about 1.2 MB, arming takes 5ms, and three 180 second idle windows measured 0.00, 2.21 and 2.29 events per second, a trickle rather than a firehose. It was rejected anyway, for two reasons that are properties of this population rather than of notify. The values a cheap watch of `.git` can see, the branch and the two ahead/behind counts, cost 0.15 seconds to recompute for all 403 entities, so the watcher would buy a value that is already free. The value that would actually justify it, the typed status counts, needs the working tree watched, and the two roots hold 6,715,405 filesystem entries of which 78% are inside `node_modules`. Prior art agrees: lazygit contains no `fsnotify` anywhere in its source and polls instead, gitui reverted watching to an opt-in `--watcher` flag, tig polls `lstat` on named files inside the gitdir, and magit runs no timer-driven refresh at all. The one Rust tool found watching many repositories had to pass `NoCache` explicitly, because the convenience constructor's default file-id map allocated 1.87 GiB on this tree and had still not finished arming after 121 seconds.

What replaces the watcher is cheaper than the watcher: a sweep of `HEAD`, `index`, `packed-refs` and `refs/` across all 441 entities costs 1.79ms, and runs every 2 seconds, which is lazygit's own external-change-detection interval. Its blindness is stated rather than engineered around. It sees a commit, a checkout, a stage and a hard reset; it misses an unstaged edit, an untracked file, and a fetch, the last because `refs/remotes/origin/` gains an entry without moving the mtime of `refs/` itself.

A refresh is a generation, and an abandoned generation is cancelled rather than left to finish. lazygit and gitui both take the other option, letting the old refresh run to completion and dropping its write on arrival, and that is what this design expected to copy. Measured, letting it run costs 1.79 times the next generation's wall clock, because two generations contend for the same eighteen cores and the second pays for both. Setting gix's `should_interrupt` flag instead brings the next generation in at 1.04 times a cold run. The flag is checked per index entry, so a single Repo stops in 0.5 to 0.9ms, and a whole generation stops in about 250ms, nearly all of which is tasks that had not started yet still doing `gix::open` before reaching their first check. The difference from the prior art is scale: lazygit and gitui refresh one repository, Repon fans out over 403. Cancellation is cooperative, so late results still arrive and must still lose, which is why every result carries the generation that produced it and the comparison happens at the point of writing the cell rather than at the channel. That also makes supersession per entity rather than global, so a refresh scoped to the Selection cancels work only for the entities it covers and cannot strand the four hundred rows it never spoke for. Mechanics live in [the refresh spec](../spec/refresh.md).

The recorded cost model was wrong, mostly in the comfortable direction. The full probe of every entity is 4.4 seconds rather than 7.2, boundary-stop discovery is 19ms rather than 0.54 seconds, opening a Repo and reading its branch is 0.4ms rather than 10ms, and the status median is 11ms uncontended rather than 94ms. Two figures were wrong in ways that changed the design. Subsetting the expensive phase to the visible rows does not bound its latency: twenty rows took 1.145 seconds where ninety-four took 0.633, because one 40,000 file monorepo happened to sit in the first twenty. Visible-first is therefore an ordering and not a scope, and a refresh always covers every entity. And `.git` size does not predict probe cost, since `baseweb` carries 317 MB of `.git` and costs 47ms while `squad-metadata` carries 4 MB and costs 91ms, so the ordering is by position rather than by any cost heuristic, and the real predictor, working-tree file count, costs a full walk to learn. One further check settled a worry about the watcher that no longer matters but is worth recording: a gix status writes nothing at all, verified by a recursive snapshot of every file under `.git` taken before and after a full probe and found byte-identical, so Repon's own reads can never be mistaken for someone else's changes.

## Consequences

- Filesystem watching is closed rather than deferred, and the map's fog entry for it goes with it. A future reader will want to add notify, because the watcher measured cheap and the idle event rate is a trickle. It is cheap; what rules it out is the working-tree scope it needs and the freeness of what a cheaper watch would detect, and both of those are facts about this population.
- gix's per-repository thread limit is set to 1 and the fan-out is one rayon task per entity. Measured at 3.36 seconds wall and a 44.6ms median, against 4.50 seconds and 88.9ms with gix's own parallelism left on, because gix's status is internally parallel and a 403-way fan-out oversubscribes eighteen cores by an order of magnitude. This is not a config key: it is a measured property of two libraries rather than a taste, and exposing it would invite someone to make it worse.
- Unknown carries a reason. Timed out, no upstream and no default branch are all Unknown and all render `?` in the gutter; the detail pane says which. A sixth provenance state was rejected because it would cost a sixth glyph, a new disjointness obligation under [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md) and a reopened [0001](0001-per-cell-provenance.md), for a distinction that only matters once someone has looked at the row.
- The deadline belongs to the generation, not the cell. A rayon task cannot be pre-empted, so a per-cell deadline could only mark a cell while the work carried on underneath it, and a probe that is still running has not asked and got nothing back. A generation is cancelled at 30 seconds, comfortably clear of the measured 4.4, and every cell still Loading in it becomes Unknown at that moment.
- The spinner may appear in a cell as well as in the gutter, which amends [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md). While a row holds no values the spinner sits in the gutter, one moving character per row; once only some cells are outstanding it moves into those cells, because after the cheap phase lands in 0.4ms the branch is settled while the status is not. This is not the per-cell variant 0010 rejected, which put a glyph in every cell for every state.
- Six configuration keys fall out and belong to [Design the config schema](https://github.com/paulchiu/repon/issues/9): `refresh.poll_interval` (2s, 0 disables), `refresh.status_stale_after` (5m), `refresh.on_focus` (true), `fetch.enabled` (false), `fetch.interval` (5m) and `fetch.concurrency` (4). The fan-out shape is deliberately not among them.
- The periodic fetch must prune or Gone never appears at all, and 191 of the 203 Repos with remotes point at github.com, which documents a ceiling of roughly 15 read operations per second per repository and warns about automated read traffic, so its concurrency is bounded rather than fanned out.

## Amended by 0019

`Unknown`'s closed set of reasons shrinks from four to two. `NoUpstream` and `NoRemote` are removed, because a branch that tracks nothing renders `-` and a Repo with no remote renders `∅`, both values behind a blank gutter, and `base` is already Not applicable in the second case. Each was a settled fact wearing a missing one's mark, and the contradiction was live: the same fact rendered blank with `?` in [core-api.md](../spec/core-api.md) and as `-` on 16 Submodule rows in [discovery.md](../spec/discovery.md). `TimedOut` and `NoDefaultBranch` remain, and the set stays closed. Closed bounds how the set changes, not its size: a third reason, `SubmoduleUninitialized`, was added later for the uninitialised Submodule row, which [core-api.md](../spec/core-api.md) carries. See [0019](0019-a-detached-head-is-a-shape-of-head-not-a-worktree-state.md).
