# The active Set names the status row, and the picker is the tab strip

The active Set's name replaces the program name in the status row's first item, so rank 1 reads `work 403 entities` where it read `repon 403 entities`. There is no tab strip: `s` draws the Set picker, one row per declared Set in file order with its `1` to `9` number beside it, and that is the strip. The name is never truncated: it renders whole, or its item drops whole under the one drop table [0026](0026-the-status-row-is-one-list-not-a-stack-of-surfaces.md) fixed for that row. Switching Set raises a Notice naming the Set switched to, and a digit past the last declared Set answers with one instead of doing nothing. This settles the question [0025](0025-a-name-that-bounds-the-work-is-never-substituted.md) raised and ticketed, that by the design of record the most consequential piece of session state Repon holds appeared on screen nowhere.

A strip is refused on the vertical arithmetic, which nothing had done. The reference terminal is 24 rows. The status row, the frame's top border, the column header, the frame's bottom border and the footer are five rows of chrome, leaving 19 for the table at `88x24`. A tab strip makes it 18, permanently, and it spends that row on state that changes perhaps twice in a session. [0014](0014-config-is-read-only-and-a-set-bounds-the-work.md) said "Sets are the tab strip" while settling something else, the choice of array-of-tables over a map of tables, and what it needed from the phrase was that file order fixes the numbers. That is an ordering claim. The rendering claim rode along with it and is withdrawn here.

The picker is the better strip because it is drawn when the user is choosing rather than constantly at someone who is not looking. It already exists and already lists every declared Set in file order, marking the active one; numbering each row is what turns it into the teaching surface for `1` to `9`, at the one moment the numbers are worth knowing. A strip would have had to teach them the rest of the time, to a reader whose eyes are on the table. It is also the only way to reach a tenth declared Set, since the keys stop at `9`, so its rows past the ninth carry a name and no number.

The program name is what pays for the Set name, and it costs nothing, because the leading token of `repon 403 entities` is the one thing on screen the user cannot need: they typed the command, the frame is unmistakable, and the panel's own border says `repos`. `work 403 entities` is 17 columns against 18, so the row came out a column cheaper. The name lands inside rank 1, which the drop table already makes the last item to go, so it is on screen at every width at which anything but the warning indicator is, down to 20 columns of an 88-column narrow screen. The alternative was a second reserved item beside 0026's indicator, which would have narrowed the budget for every other item at every width in order to say separately what rank 1 can say for free.

They belong in one item on their own terms. A Set bounds the work rather than the view, so the count is the size of what the Set bounds; `403 entities` with no name attached is a number about an unnamed population. Putting them in one item also means they can never disagree, which two items sharing a drop table can: the count surviving while the name it counts has dropped is precisely the reading this decision exists to prevent.

Truncation is refused rather than left to the renderer. A Set name is user-supplied and unbounded, `Buffer::set_stringn` truncates silently at a grapheme boundary (recorded in [keybindings.md](../spec/keybindings.md) for the footer, and true wherever it is called), and two Sets can share a prefix, so a rendered `wo` names neither of them while looking exactly like a name. That is [0001](0001-per-cell-provenance.md)'s plausible lie told about scope, which is the same lie 0025 refused when it made an unresolvable `--set` exit rather than substitute. Whole or nothing keeps the row total.

Two silences close with it. `App::switch_to_set` is a no-op past however many Sets are declared, so `7` with three Sets does nothing and says nothing, and `1` to `9` is advertised as a range, which makes it Built and unavailable rather than unbuilt: [0023](0023-an-unbuilt-binding-is-not-advertised-and-an-unavailable-one-answers-on-press.md) says it owes an answer on press. The switch itself is the other. Changing Set discards discovery and starts a fresh Generation, so the table empties and refills, which tells the user that something changed and not what it changed to; the Notice names it, and the row then holds the name for as long as the Set is active. This also gives [config.md](../spec/config.md)'s reload fallback, where a vanished active Set degrades to the first declared one "and says so", a place to say it that outlives the Notice.

The footer is deliberately not touched. `s` is absent from the list context's measured ladder at every width, which is 87 columns of an 88-column screen at the top rung, and adding `s set` costs 8 and drops `r refresh`. That is a second decision riding on this one, against [keybindings.md](../spec/keybindings.md)'s ladder, which is a measurement rather than a preference; the row that shows which Set you are in does not have to be the row that teaches you how to leave it, and the help overlay already carries the key.

Three consequences follow. The status row's rank 1 is the active Set's name and the entity count, which is a change to text [#131](https://github.com/paulchiu/repon/issues/131) has not built yet rather than a change to anything built. Both published ladders shift by one column, and the picker, the two Notices and the row's first item are one implementation ticket. Last, [GLOSSARY.md](../../GLOSSARY.md)'s **Set** entry claimed Sets are "seeded from directory structure", which 0014 measured and refused, since one Set per depth-1 directory yields 309 single-Repo Sets under `~/dev`; the glossary is corrected here rather than left to contradict the decision it describes.
