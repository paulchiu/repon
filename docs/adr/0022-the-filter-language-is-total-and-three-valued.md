# The Filter language is total and three-valued

A Filter is a total, three-valued predicate. Total: every string a user can type is a valid Filter, so there is no parse failure and no error to report. A term splits at its first `:`; if the text before it names a known key the term is keyed, and otherwise the whole term is a substring match on the display name. A bare word is therefore always a name, in every position, so a repository genuinely called `failed` can never collide with a reserved term and needs no escaping rule. That also means adding a key in a later version cannot retroactively change what a Filter someone already typed and stored means, which is a migration nobody would think to write.

Three-valued: a term is true, false or unprovable on a row, and a cell that has not settled answers neither the term nor its negation. Negation maps unprovable to unprovable, and only true matches. Without that rule, `-state:merged` would be plain set complement, handing back rows Repon has not finished reading as though it had read and confirmed them: [0001](0001-per-cell-provenance.md)'s absent value becoming a zero, one abstraction up. `NotApplicable` is decided false, because it means the question does not apply to this row, where `Unknown` means the question applies and Repon does not know. The accepted cost is that a term and its negation do not partition the list.

**Enforcement:** all in `crates/repon-core/src/filter.rs`. `every_input_parses_with_no_failure_and_an_empty_filter_matches_every_row` and `an_unrecognised_key_becomes_a_literal_name_search` hold totality. `a_cell_nothing_has_settled_is_unprovable_both_ways`, `a_failed_cell_is_unprovable_both_ways` and `not_applicable_is_false_so_negation_includes_it` hold the three-valued rule. `vocabulary_matches_filter_mds_own_table_in_both_directions` keeps the key set and [filter.md](../spec/filter.md) from drifting apart.
