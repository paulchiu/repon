# Discovery stops at the repo boundary, and Submodules are read rather than walked

Discovery walks each Set root and stops at the first repo boundary it meets: a directory holding a `.git` entry, file or directory alike. It never descends past one. Submodules are then reached by reading `.gitmodules` in what the walk already found, one level, never by walking deeper, and never by recursing, because unbounded recursion turns a read back into a walk. The deep walk that would find the same things costs three orders of magnitude more on a real corpus, so it can never ride the refresh, and there is no depth key, no directory denylist and no discovery budget key for it to be tuned with. A repository sitting inside another repository's working tree is reached by adding its parent as a Set root, which is a mechanism that already exists.

A directory symlink is followed only when its target is itself a Repo, and then only to record that Repo, never to walk through it, so cycles are impossible rather than guarded against. Identity is the canonical path, because the state file keys the Selection by name and two paths to one Repo would give restore-by-name two live instances; a symlink resolving to an already-discovered Repo is dropped silently, with no warning, because nothing is wrong.

**Enforcement:** all in `crates/repon-core/src/discovery.rs`: `the_walk_never_descends_past_a_repo_boundary`, `a_nested_repo_is_reached_only_by_naming_it_as_its_own_root`, `a_submodule_is_found_by_reading_gitmodules_with_the_walk_never_descending_to_it`, `a_symlink_to_an_ordinary_directory_is_not_followed_or_recorded`, `a_self_referential_symlink_does_not_hang_or_panic` and `a_symlink_resolving_to_an_already_discovered_repo_is_dropped_silently`.
