# A detached HEAD is a shape of HEAD, not a Worktree state

> **Retired.** This record is kept for its history. Its product intent now lives in
> [product.md](../product.md) and its implementation detail in
> [head.md](../spec/head.md). Nothing below is maintained.

HEAD has three shapes, and detachment is one of them, so it belongs in the `branch` cell rather than the `state` column. The four Worktree states in [0009](0009-worktree-state-model.md) survive untouched; what changes is the classification rule. Merged needs a commit and a default branch, not a branch name, so it stays computable when HEAD is detached, while Gone, Local only and Active all need an upstream a detached HEAD structurally cannot have. A detached row is therefore one computable state and three unknowable ones, which a four-way exclusive enum cannot say and `Cell<WorktreeState>` already can, because `NotApplicable` lives in the `Cell` rather than in `WorktreeState`. The population makes this the common case rather than an edge: of the 403 entities under `~/dev` and `~/dev-misc`, the same population every other ADR measures, 125 are at a detached HEAD, 121 of the 163 Worktrees (74%) and 4 of the 240 Repos. 119 of the 125 are directories named `<repo>-pr-<number>`, PR review checkouts, and all 4 detached Repos are jj (jujutsu) colocated repositories whose HEAD reflog reads `export from jj`; jj deliberately leaves the colocated git HEAD detached. Detachment here is a working style, not an accident: 0 of the 125 carry an in-progress operation marker, 0 have a tag pointing at HEAD, 10 have some ref pointing exactly at HEAD, and 9 are Dirty. Mechanics live in [head.md](../spec/head.md), and the vocabulary is [GLOSSARY.md](../../GLOSSARY.md)'s.

The three shapes are taken from gix one to one. gix 0.87.1's `head::Kind` has exactly three variants, `Symbolic`, `Unborn` and `Detached { target, peeled }`, verified in `src/head/mod.rs` of the vendored crate. `Detached` gives an object id and no referent name; `Unborn` gives a referent name and no object id, the exact mirror: a branch name and no commit, against a commit and no branch name. Both non-symbolic shapes have live rows, the 125 detached entities above and 2 at an unborn HEAD (`HelloWorldCLI` and the planning directory itself), both showing git's `## No commits yet on main`.

`state` computes Merged. On a detached row it is `Known(Merged)` when ancestry or patch equivalence proves it and `NotApplicable` when neither does, so the cell carries a positive answer or nothing. Measurement is why this earns its cost: 2 of the 125 are ancestors of the default branch and a further 53 are patch-equivalent to a commit on it, so 55 of 125 (44%) read Merged. Computing it takes the `state` column from 42 to 96 of 403 rows carrying a value and makes 54 of 163 Worktrees read Merged, which is the safe-to-sweep signal [0009](0009-worktree-state-model.md) exists for. The alternative considered first was extending [0017](0017-discovery-stops-at-the-repo-boundary.md)'s blanket Not applicable from Submodules to Worktrees, which discards Merged on 74% of Worktrees, on exactly the entities whose owner most wants a sweep check. A fifth exclusive state was rejected because it would be exclusive with Merged, which measurement says is wrong for 44% of the population. An orthogonal flag beside Dirty was rejected because the branch cell already carries the fact.

`branch` carries the short object id alone: no marker word, no prefix, one rule for Submodule, Worktree and Repo alike, which extends [0017](0017-discovery-stops-at-the-repo-boundary.md)'s Submodule rendering rather than amending it. The abbreviation is a fixed length rather than git's own, because `core.abbrev auto` scales with object count (measured at 9 characters in one Repo and 7 in another), so a mixed list would be ragged, and nothing consumes the id as an input, so uniqueness is not load-bearing. The cost is stated with open eyes rather than buried: an object id is a legal branch name, so the cell holds two categorically different things and the detail pane is the only discriminator, the trade [0017](0017-discovery-stops-at-the-repo-boundary.md) already accepted for 16 hidden Submodule rows and which now covers 141 rows. Colour cannot be the discriminator, because [theming.md](../spec/theming.md) forbids colour as the only carrier of meaning, so the branch cell keeps the ordinary text role in all three shapes. A `detached` Filter term makes those rows reachable without opening the detail pane, on the precedent of the `failed` term [actions.md](../spec/actions.md) added. Prior art converges on the same slot: git's own `status`, tig (`src/status.c`) and lazygit all put "HEAD detached at `<ref-or-sha>`" where a branch name would go, gitui puts the literal string `HEAD` there through libgit2's `shorthand()` fallback, and magit's `magit-list-repositories`, the only genuine multi-repo list surveyed, leaves the cell blank. No surveyed tool invents a state value for detachment. Repon takes the same place, the branch slot, and the barest content, the id.

The reflog was measured and killed as a way of recovering the branch a detached HEAD came from. All 125 entities have a `logs/HEAD` file, 107 have entries that never name a ref, and of the 16 that do, 10 say `FETCH_HEAD`, leaving 6 of 125. `git worktree add --detach` writes a reflog entry with no message field at all, which is also why git's own `git status` degrades to "Not currently on any branch." with no sha for exactly this population. Even a recovered name does not fit: one of the six is `origin/feature/stab-1957-phase-35-retire-the-unleash-flag-and-require-the-cloudflare` against a 24-column cell.

`sync` shows `-`, and settling that resolves a contradiction older than this ticket. Two settled documents gave the same fact two mutually exclusive renderings: [core-api.md](../spec/core-api.md) had `Unknown::NoUpstream`, "The branch tracks nothing", rendering blank with `?` in the gutter, while [default-branch.md](../spec/default-branch.md) and [discovery.md](../spec/discovery.md) render the same fact as `-`, a value behind a blank gutter, on all 16 Submodule rows already on screen. `-` wins, because it is in [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md)'s value glyph set and it is what is already drawn. `Unknown::NoUpstream` and `Unknown::NoRemote` are deleted from the closed set, leaving `TimedOut` and `NoDefaultBranch`: `∅` is a value for a Repo with no remote and `base` is already Not applicable there, so neither reason had a live case. The gloss "`-` means you could push and have not" is corrected, being false for a detached HEAD and false for all 16 Submodules already carrying `-`. It named [default-branch.md](../spec/default-branch.md), which never carried it; the sentence is at [layout-and-provenance.md](../spec/layout-and-provenance.md) and was left standing until [0020](0020-the-ascii-glyph-set-is-vetted-over-the-row-interior.md).

`base` is computed and shown, and this is where 0017's reasoning does not transfer. [0017](0017-discovery-stops-at-the-repo-boundary.md) says Submodule `state` is Not applicable "because none of Merged, Gone, Local only or Active means anything without a branch". Measurement shows Merged does mean something without a branch, so that reasoning is wrong even though the answer is right. The real reason a Submodule's `state` and `base` are blank is that [0012](0012-the-default-branch-is-a-remote-tracking-ref.md) records that population's default branch as known-wrong with no local detector, a cached `master` where the truth is `qmk-master`, so a Merged computed against it would be a confident lie. Detachment was a coincidence in that population, not the cause. The rule becomes "no trustworthy default branch, so no proof", and on a Worktree, where the default branch resolves normally, both cells compute. `base` is computable on all 125 detached entities: median 46 commits behind the default branch, p90 286, max 530, 5 at zero. One consequence falls out for the 4 jj colocated Repos: [default-branch.md](../spec/default-branch.md) exempts a row whose branch is itself the default branch from `base`, a detached Repo has no branch, so `base` goes live and non-zero on repositories their owner considers entirely normal.

The environment contract splits the shapes cleanly. `REPON_BRANCH` is unset on a detached HEAD, by [config.md](../spec/config.md)'s existing rule that an Unknown or Not applicable value unsets the variable rather than setting it empty. A new `REPON_HEAD` carries the resolved commit id of HEAD in every shape that has one, so a step that wants the commit can have it and a step that wants a branch gets nothing rather than something wrong. Without this, "The current branch" would be set to an object id on 121 of 163 Worktrees, and `git push -u origin "$REPON_BRANCH"` in a `shell = true` step would push a sha as a branch name. This is the defect class [0018](0018-an-action-is-a-fanout-of-pty-backed-steps.md) closed for `REPON_DEFAULT_BRANCH`, one variable over.

In-progress operations are reported, in the detail pane only. gix 0.87.1 has `Repository::state() -> Option<state::InProgress>` with ten variants covering rebase, interactive rebase, mailbox apply, cherry-pick, revert, merge and bisect, needing no new cargo feature and reading the per-worktree git dir, which is where git writes the markers for a linked Worktree. Its ten marker stats across all 403 entities cost 6.55ms, with 0 hits in the population. It earns its place because a Worktree stopped mid-rebase and a PR review checkout are both "detached at a sha" and would otherwise render identically. It is not a state, not a gutter mark and not a gate on an Action: [0002](0002-repon-owns-the-outer-loop-only.md) says report rather than fix, and refusing an Action the user typed is fixing.

The gutter renders a space on a detached row, accepted with open eyes. `NotApplicable` cells are excluded from the row summary fold, so a detached row whose `state` is blank folds to Fresh and the gutter shows a space, claiming the row is known and current on 125 rows where `state` has no opinion. A Repo row already does exactly this on 240 rows, because its `state` is Not applicable by kind, and [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md) accepted that when it wrote the rule: the gutter summarises provenance, not completeness. The alternative puts `?` on 125 of 403 rows for a settled fact, which is the lie [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md) exists to prevent, one direction over.

Patch equivalence must be memoised per common dir, and writing that down closes a gap a settled figure depends on. The 123 detached entities that need the pass sit in only 14 distinct git common dirs, 110 of them in three. The expensive half of the proof, the default branch's patch-ids, depends only on the common dir and the deepest merge base, so computing it once per common dir takes the pass from 321 seconds to 20.7 seconds serial: 10.67 seconds over 14 shared scans plus 10.04 seconds over 123 per-entity diffs at 82ms each. [default-branch.md](../spec/default-branch.md)'s two-passes section never states this, so its recorded 130ms per branch is reachable only with a memoisation nothing wrote down. It is keyed the same way the `origin/HEAD` read already is, per common dir per Generation.

One report was measured and rejected: "detached with work that exists nowhere else". 43 of 125 detached entities hold committed work reachable from no ref and not landed, and Dirty sees only 2 of them, so it is a real second danger Dirty cannot see. It costs a full reachability walk, measured at 5.1 seconds serial marginal across the 125 entities against [refresh.md](../spec/refresh.md)'s 4.4 seconds for the entire probe. The Merged proof already answers the question that has an action attached, and Repon does not manage Worktrees by design, so the pass more than doubles the probe to report something the user cannot act on from here.

## Consequences

- [0009](0009-worktree-state-model.md)'s four states survive untouched. The classification rule changes: Merged asks for a commit and a default branch, Gone, Local only and Active ask for an upstream, and a detached HEAD has the first pair and structurally cannot have the second.
- [0017](0017-discovery-stops-at-the-repo-boundary.md) keeps its answer and loses its reason. A Submodule's `state` and `base` stay blank because [0012](0012-the-default-branch-is-a-remote-tracking-ref.md) records that population's default branch as known-wrong with no local detector, not because the states mean nothing without a branch.
- `Unknown` shrinks from four reasons to two, `TimedOut` and `NoDefaultBranch`. That is a change to a set [0013](0013-no-filesystem-watching-a-refresh-is-a-cancellable-generation.md) declared closed, recorded here as such.
- The "`-` means you could push and have not" gloss is corrected, in [layout-and-provenance.md](../spec/layout-and-provenance.md), which is where it actually sat rather than in [default-branch.md](../spec/default-branch.md) as this ADR first said; that miss was caught and fixed by [0020](0020-the-ascii-glyph-set-is-vetted-over-the-row-interior.md). default-branch.md's two-passes section gains the per-common-dir memoisation its 130ms figure silently assumes.
- [refresh.md](../spec/refresh.md)'s patch-equivalence population is corrected from "about 163" to 176 entities: 11 Repos, 42 attached Worktrees and 123 detached, measured across the whole population. Its poll evidence table gains a row, because a commit on a detached HEAD writes the new object id straight into the per-worktree `HEAD` file, which is better evidence than an attached row gets, where refresh.md already warns a commit does not touch `HEAD` at all.
- [core-api.md](../spec/core-api.md)'s `branch` cell changes type, carrying the shape of HEAD rather than a branch name alone.
- [config.md](../spec/config.md)'s environment table gains `REPON_HEAD`, set in every shape that resolves to a commit and unset on an unborn HEAD.
- The mechanics live in a new spec, [head.md](../spec/head.md).
