# The core owns the table, and only the core supersedes

repon-core owns the assembled table of entities and their state, only repon-core applies supersession, and its public surface is a snapshot the consumer reads, not a channel of cell updates. What forces this is a rule [0013](0013-no-filesystem-watching-a-refresh-is-a-cancellable-generation.md) already fixed and [refresh.md](../spec/refresh.md) records: "the comparison happens at the point of writing the cell, not at the channel". Whoever writes a cell must hold that cell's previous generation, so whoever writes owns the state. A bare channel of cell updates as the public API leaves the state in the consumer, and every consumer then reimplements per-cell Generation bookkeeping: a second apply loop kept consistent by hand, the failure [0005](0005-rendering-agnostic-core.md) exists to prevent, arriving through the API instead of a widget layer. The comparison is per cell against that cell's own recorded Generation, never against a global current: a refresh scoped to the Selection leaves the entities it did not cover on their older Generation, their results still accepted, where a global 'drop anything below the current' check would strand exactly the rows a Selection refresh never spoke for.

Cost did not decide it, because every candidate shape fits. Measured on an 18 core machine against the real population, 403 entities of 7 cells: cloning the whole table with `Arc<str>` payloads costs 35 microseconds against a 16.7 millisecond frame at 60 frames per second; an `RwLock` read of that clone, while 18 rayon workers wrote 2,370 full rounds over two seconds, gave 124 microseconds mean and 367 worst per frame, pressure far heavier than a real Generation, which writes each cell once over 4.4 seconds; a fine channel of 2,821 cell messages cost 604 microseconds to send and 51 to drain and apply, a coarse channel of 403 per-entity messages 263 and 44. So the decision was made on correctness. The one alternative genuinely cheaper to read, `arc-swap` at 41 nanoseconds per load, cannot mutate a single cell: a writer must build and publish an entire new snapshot, so the core would need a staging buffer and a publish cadence, which buys nothing when the only caller is a render loop that was going to draw anyway. If the entity count grows an order of magnitude, this is the measurement to retake.

Two independent codebases arrived at the same shape. gitui's `asyncgit` sends a payload-free `AsyncGitNotification` over a crossbeam channel and keeps the data in a `Mutex` guarded 'last known' slot read through a getter; helix's `helix-vcs` does the same with an `Arc<RwLock<DiffInner>>` and a `tokio::sync::Notify` carrying no payload. Neither streams the value over the channel. asyncgit also shows the bug of splitting state from the supersession check: `fetch_helper` and `get_diff_helper` compare a request hash before writing the request cache, then write the `last` slot consumers actually read unconditionally, so a slow superseded task can still clobber what is on screen, the defect Repon's write-time comparison makes impossible and prior art to learn from rather than copy. Repon takes the shape without the notification channel: the skeleton's `tui.next_event()` is a blocking receive on one channel, no `crossbeam::Select` anywhere, unlike gitui's own `main.rs`, so a second channel would not wake the loop, and the event thread already posts a render event 60 times a second, so a 35 microsecond snapshot read on a frame being drawn anyway costs nothing worth a channel.

A cell is four settled answers, `Unknown` with a reason, `Known` with a value, a timestamp and a staleness flag, `Failed` with an error, and `NotApplicable`, plus an orthogonal in-flight flag; this amends [0001](0001-per-cell-provenance.md), which named five states with Loading among them. [refresh.md](../spec/refresh.md) already stopped treating Loading as a peer when it recorded that in-flight is a row property outranking the least-settled-state summary, so the amendment only writes down what the refresh model already does; and a flat five-arm enum cannot satisfy [layout-and-provenance.md](../spec/layout-and-provenance.md)'s rule that on a re-probe the cell keeps its previous value, because a `Loading` arm carrying no value loses it the instant a re-probe starts. `NotApplicable` is a settled answer rather than an absent value for the reason [the default branch ADR](0012-the-default-branch-is-a-remote-tracking-ref.md) already gives for not marking a no-remote Repo's `base` column unknown: a settled fact, not a missing one, where an `Option<Cell<T>>` would reintroduce a bare `Option` a consumer can default around, the hole 0001 exists to close. The five states a reader sees on screen under [0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md) are unchanged; the type just stops modelling in-flight as one of them.

The core owns discovery, the four probe phases, the metadata poll, a Set as a bounding specification it is handed, per-Repo overrides, the Generation counter and supersession, the fold of a row's cells into one summary state, an entity's display name, the default branch's resolved rung and its rung-2 against rung-3 disagreement, the environment contract for a child process expressed as data, and Action fan-out. The consumer owns the terminal, the Launcher end to end, config file discovery and parsing, when a Filter is applied, the cursor, every glyph, the theme and the keybindings. jj states the principle more sharply than [0005](0005-rendering-agnostic-core.md) did: its library "cannot read configuration from the user's home directory, or from user-specific environment variables". The neighbouring claim, that a library never spawns a child process, is false: jj's own library calls `Command::new` in `lib/src/git_subprocess.rs`. The line is the terminal, not the process. The surface itself, type by type, lives in [the core API spec](../spec/core-api.md), not here.

Three places had already leaked a screen into the vocabulary and are closed here. The Selection's default was defined as the row under the cursor, so [GLOSSARY.md](../../GLOSSARY.md) is amended to drop it and the core attaches no meaning to an empty list. Phase C's dispatch order was defined as cursor row first, so the core takes an already-ordered list of keys, free because that order was already 'by position, not by predicted cost'. And a Filter narrows what is visible, so the core owns the predicate as a pure function over the public types, keeping one implementation, while the consumer decides when to apply it.

A crate boundary is necessary and not sufficient, and the evidence is harder on it than [0005](0005-rendering-agnostic-core.md) assumed. ripgrep's `grep-*` crates are the one unambiguous success, held because real third parties depend on them; jj writes almost exactly 0005's rule, has by its maintainers' own admission never proven it against a second consumer, and tells third parties to parse CLI output instead; asyncgit has been standalone for years without a meaningful second consumer; Cargo's own team looked at guaranteeing their library boundary and declined. Repon today has no CI, no cargo-deny and no clippy configuration at all. So the enforcement is a second consumer that actually exists. `repon sets`, which [0014](0014-config-is-read-only-and-a-set-bounds-the-work.md)'s spec already requires to print each Set's name, roots and match count, needs discovery with no terminal, no probing and no provenance, and is built as a literal second consumer of the same API the terminal interface calls, never a special case. Beside it sits one CI line asserting repon-core's dependency tree contains no ratatui and no crossterm, free because it already passes. Nothing else: no cargo-deny, no sealed traits, no separate versioning, and no `#[non_exhaustive]`, which was measured to force every consumer to add a wildcard match arm even when it already matches every variant, reintroducing by attribute the 'just show the number' default path 0001 forbids; gix 0.87.1, a heavily depended-on pre-1.0 crate, barely uses it either.

## Consequences

- The core carries its own clocks: the two second metadata poll, the thirty second Generation deadline and the five minute status staleness threshold. It is `Core::start()` rather than `Core::new()`, so a constructor that spawns threads is not a surprise, and `Drop` joins them; probes stay on rayon's global pool, as the existing fan-out already does.
- Cloning a cell per frame is a requirement no ADR previously stated; it follows from the snapshot, not from [0001](0001-per-cell-provenance.md). The placeholder `Box<dyn std::error::Error + Send + Sync>` is not `Clone` and cannot survive, so a failed cell carries a small `thiserror` enum whose variants hold `Arc<str>`.
- The read-only invariant is scoped to the probe path. `git.rs` says "gix reads; nothing here writes" and the manifest says "read-only surface by choice", but the periodic fetch always prunes, which mutates `refs/remotes/`; fetch is a separate mutating path, and the comment is corrected to say so. This is amended: fetch shipped behind its own cargo feature at first, off by default, so an ordinary install carried none of gix's blocking network client, HTTP transport or credential machinery, and that left `cargo install repon`'s own binary unable to do the one thing `fetch.enabled = true` in `config.toml` asked it for, silently, the setting parsed, stored, and never run. Fetch is unconditional now, in both crates, published library included: the read-only invariant stays scoped to the probe path exactly as stated above, but the boundary that scopes it is no longer a cargo feature, only the crate's own mutating-path split between `fetch.rs`/`auto_update.rs` and everything else.
- `gix::Repository` is `Send` and `Clone` but not `Sync`, because it holds a `RefCell` free-list of buffers, verified by compiling against 0.87.1's exact feature set; `ThreadSafeRepository` is `Send`, `Sync` and `Clone`. One `Repository` per rayon task, never shared.
- `std::time::Instant` cannot be serialised and `SystemTime` serialises to a `secs_since_epoch` and `nanos_since_epoch` pair no consumer wants, so a settled cell carries a wall-clock timestamp rendered as RFC 3339. Supersession never reads it, so a clock that jumps backwards renders as 'just now' rather than being defended against.
- `Arc<str>` does not implement `Serialize` under serde's default features, so the core's optional serde feature turns on serde's `rc` feature with it.
- A Repo that vanishes between Generations stays in the snapshot with its last values, every cell Stale, until dismissed, and the dismissal never persists, because a Generation 1 with an empty prior state cannot produce one. An entity that moved reads as vanished plus new, the same trade the Selection already takes when it restores by name.
- The machine-readable consumer emits one settled document rather than a stream, because streaming without a notification channel would mean polling and diffing the snapshot, a second supersession implementation in the place this decision removed one.
- `fanout` and `git` become private modules. What is public is the vocabulary [GLOSSARY.md](../../GLOSSARY.md) already names, so that reading the crate root and reading the glossary give the same answer.
