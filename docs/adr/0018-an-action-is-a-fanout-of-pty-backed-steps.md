# An Action is a fan-out of PTY-backed steps, and its result is a receipt rather than a reading

An Action's result is a receipt of something Repon did, not a reading of the world. A receipt records that a command ran, where, and how it exited, which no later look at the filesystem can contradict. So it is never a `Cell`: it never goes Stale on a poll, is never superseded by a Generation, and never persists. It lives in memory and dies with the process. What the world looks like after a run is the next Generation's question, asked through the same path as every other reading.

A step's child goes into a new session with `setsid(2)` in `pre_exec`, which cannot be combined with `CommandExt::process_group(0)`, since `setpgid` then `setsid` fails with EPERM. The new session is mandatory rather than an optimisation: it lets `killpg` reach grandchildren, it detaches the controlling terminal so a step cannot write over Repon's alternate screen, and it keeps a group kill off Repon's own process group. stdin is `/dev/null`, because a child that inherits stdin and reads it hangs forever while holding a concurrency slot. stdout and stderr share one PTY slave, so a child's colour survives capture. The stop verb is SIGTERM to the group and SIGKILL after a grace, because SIGTERM is trappable. The fan-out runs on its own pool sized by `concurrency`, never on rayon's global pool, because a step blocked in `wait()` removes a worker rayon does not replace, starving the refresh.

**Enforcement:** in `crates/repon-core/src/executor.rs`: `the_childs_process_group_equals_its_own_pid_because_setsid_made_it_a_session_leader`, `stdin_is_wired_to_the_null_device_literally_not_merely_inherited`, `a_child_that_traps_sigterm_still_dies_once_cancel_escalates_to_sigkill`, `a_steps_own_program_sees_the_pty_on_stdout_and_stderr_and_nowhere_else` and `colour_escape_sequences_survive_capture`. `an_action_steps_child_never_uses_the_process_group_call_setsid_is_exclusive_with` in `crates/repon/src/test_support.rs` bans the incompatible call across production source, and `the_actions_own_pool_never_starves_a_refresh_dispatched_on_the_global_pool_while_it_blocks` in `crates/repon-core/tests/action_dedicated_pool.rs` holds the pool split. `no_source_file_writes_an_action_receipt_to_disk` in `crates/repon/src/components/detail.rs` holds the receipt's never-persists half; `ActionReceipt` is a type of its own rather than a `Cell`, so the never-superseded half holds by construction.
