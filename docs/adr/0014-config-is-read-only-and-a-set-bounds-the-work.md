# Config is a file Repon only reads, and a Set bounds the work

> Superseded in part by [0028](0028-repon-writes-the-repo-entries-it-owns.md), which lets Repon write `[[repo]]` entries. Everything else below stands: no config watcher, no first-run materialisation, and nothing the user hand-wrote is ever rewritten.

Config is `~/.config/repon/config.toml` with a `themes/` directory beside it, on macOS as well as Linux; state and the log stay at the platform data directory, which on macOS is `~/Library/Application Support/repon/`. The split is the one tuicr already uses on this machine (config at `~/.config/tuicr/config.toml`, data at `~/Library/Application Support/tuicr/`), kept deliberately so two of the same person's tools do not disagree. The surprise a future reader needs: the skeleton resolves both paths from the `directories` crate's `ProjectDirs`, which ignores `XDG_CONFIG_HOME` on macOS by design, so `config_local_dir()` returns Application Support. The config half moves to `etcetera`'s `choose_base_strategy`; the data half keeps `directories`. Of eleven comparable tools, seven default to `~/.config` on macOS (gitui, yazi, jj, atuin, starship, helix, television) and four to Application Support (lazygit, zellij, superfile, bottom); jj argued its own move to `etcetera` rather than drifting into it, its author writing "I do not believe that it is correct in any way to place configuration in ~/Library/Application Support, ever, and certainly not for CLI applications." Two claims did not survive verification and must not be repeated: lazygit does not check `~/.config` on macOS (the PR proposing it is open, not merged), and gitui has no `GITUI_CONFIG_DIR` (also an open PR; a code search returns zero hits). Eight of eight tools checked ship an environment variable overriding the config path, so `REPON_CONFIG` and `REPON_DATA` stay.

Repon never writes `config.toml`. GLOSSARY.md calls a Set "a named, saved predicate", and saved means written down by the person in the file, as against a Filter, which is transient; writing it back would mean round-tripping a hand-edited document, which the pinned `toml` 1.1.4 cannot do without dropping every comment, and keeping them would need `toml_edit`. Two reasons not to: the predecessor's own record puts "editing config inside the app" and "a config file watcher" in its explicit out-of-scope list, and the owner's tuicr config is a file whose comments carry more information than its values. So there is no first-run materialisation of a default file: `repon config --example` prints the annotated example to stdout, and the redirection is the user's.

When the file is wrong, the answer depends on which kind of wrong, because three documents held three policies before this: `config.rs` errors on a malformed config, theming.md warns and falls back to the compiled default for a malformed theme, and [0006](0006-no-git-state-cache-session-state-by-name.md) says a corrupt state file behaves exactly like no file. The distinction that resolves it: a wholly defaulted Repon has no roots, so it scans the working directory, and that is not a degraded view, it is a different program pointed somewhere else. Measured, boundary-stop discovery costs 0.19s over `~/dev` and 0.045s over `~/dev-misc`, but from `$HOME` it had not finished after 100 seconds, having walked 1.45 million entries to find 34 Repos, because `~/Library` has no `.git` to stop at. So malformed TOML, or a bad value in a known key, exits non-zero before the terminal is claimed, and `App::new()` calling `Config::new()` before `run()`'s `tui.enter()` becomes a stated invariant with a test rather than an accident of ordering. An unknown key warns and Repon continues, via `serde_ignored`, which reports every unknown key's dotted path in one pass where `#[serde(deny_unknown_fields)]` aborts on the first.

A Set bounds the work; it does not filter a view. A Set is roots plus optional include and exclude globs, and an entity a Set excludes is never discovered and never probed. That separates it from a Filter, which narrows what is on screen and never changes what is computed. The recorded requirement behind the distinction is that named sets "avoid paying for filtered-out repos". With no config file at all there is exactly one implicit Set, `all`, rooted at the working directory, which is what keeps zero config zero. The original intent was Sets seeded from directory structure, and the measurement is why that does not happen. On the owner's corpus, boundary-stopped: `~/dev` holds 309 entities, every one at depth 1, being 148 `.git` directories and 161 `.git` files, Worktree siblings named after tickets (`manage-pr-4273`, `serve-frontend-cad-1585`); `~/dev-misc` holds 94, of which only two directories group anything real (`poe-editor-pocs` with 4, `vscode-extensions` with 3). One Set per depth-1 directory would produce 309 single-Repo Sets under `~/dev` and nothing anyone would use, so the implicit `all` Set is the whole of the seeding and structure is not consulted.

Discovery itself is bounded by time, not by configuration: no `max_depth`, no denylist, no wall-clock budget in the file, because each would pre-empt [Decide the discovery strategy and how submodules are reached](https://github.com/paulchiu/repon/issues/13), which owns the walk. Instead, at one second still walking, a warning names the directory count reached and the roots; at thirty seconds discovery is abandoned, Repon shows what it found, and the warning becomes persistent. Time is the trigger rather than a directory count because a count threshold is machine-specific (an SSD and a network mount differ by two orders of magnitude) where a second is a second, and the count is what the message carries, because it is the number that tells you how wrong your working directory is. The one second is anchored on [refresh.md](../spec/refresh.md)'s own first-frame budget, names on screen within 50ms and cheap columns within 200ms, against a measured 19ms for 403 entities.

The file's shape is array-of-tables uniformly: `[[set]]`, `[[launcher]]`, `[[action]]` and `[[repo]]`, each carrying a `name` (or a `path`), with file order as tab order and palette order. Measured against serde 1.0.229 and toml 1.1.4, array-of-tables preserves file order for free and permits duplicate names silently, while a map of tables (`[set.work]`) catches a duplicate key at parse time but orders lexicographically unless the `toml` crate's `preserve_order` feature is turned on, pulling in indexmap. Order is load-bearing for both uses (Sets are the tab strip, the Launcher palette is a list), and Repon can catch a duplicate name itself in one line, so the array form wins and there is one shape to learn. The field-by-field schema lives in [the config spec](../spec/config.md), not here. A shipped default Launcher is overridden by declaring one with the same name, and `disabled = true` drops it.

## Consequences

- The skeleton's `config_dir()` must move to `etcetera`; `data_dir()` stays on `directories`. This is recorded, not done: the map's destination is decisions, not features.
- There is no `toml_edit` and no config file watcher. Reload is an explicit keystroke that re-reads the file the user has edited in another window, its key owned by [Decide the keybinding map](https://github.com/paulchiu/repon/issues/12); everything reloads in place except a change to a Set's `roots` or globs, which discards discovery and starts a fresh Generation.
- Durations are humantime strings throughout, so `refresh.poll_interval = "2s"` and the disabled poll is `"0s"`. This amends [refresh.md](../spec/refresh.md), which spelled it `0`: measured, `humantime-serde` rejects a bare TOML integer with `invalid type: integer 2, expected a duration`, so the spec's own disable value was a parse error under the readable representation.
- The per-Repo override from [0012](0012-the-default-branch-is-a-remote-tracking-ref.md) is `[[repo]]` with `path`, `default_branch` and `exclude`, matched by git common dir rather than by entity path. Measured, `manage` has 45 linked Worktrees as depth-1 siblings, `manage-frontend` 60 and `serve-frontend` 28, so a path-keyed table would need 46 entries to say one thing about `manage`; `exclude = true` means listed and never operated on, which differs from a Set's exclude glob, where the entity is never discovered.
- Once discovery is abandoned it leaves the refresh path and becomes manual until `roots` change, because [refresh.md](../spec/refresh.md) re-runs discovery at the start of every Generation and a thirty second walk every two seconds is not a degraded mode.
- The status bar carries one warning slot, not three. [theming.md](../spec/theming.md) specified `theme: 2 warnings`, and config warnings and an abandoned discovery would each want their own word; one slot shows the most severe outstanding condition and expands to a list on a keystroke, which amends theming.md.
- Actions get their fields here and their behaviour elsewhere. A new ticket owns output capture, the run pane, what failure means, cancellation, and how a run's result persists; writing execution semantics inside a config document would bury them.
- `show_worktrees` and `show_submodules` are preferences in the file, and a Filter beats them. Turning on a Worktrees-only Filter while the preference is off shows them and says so in the header, because an explicit gesture beating a stored preference is the same rule [0006](0006-no-git-state-cache-session-state-by-name.md) applies to flags beating stored state, and the alternative is an empty list that reads as a broken config.

## Amended by 0027

"Sets are the tab strip" is withdrawn as a rendering claim and kept as an ordering one. File order fixes the `1` to `9` numbers, which is what this decision needed from the phrase when it chose array-of-tables over a map of tables; no strip is drawn. A strip costs one of the 19 table rows at `88x24` permanently, for state that changes twice a session, so the picker `s` and `Tab` open carries the numbers instead, and the active Set's name is the first item of the status row, where the program's own name used to sit. See [0027](0027-the-active-set-names-the-status-row-and-the-picker-is-the-strip.md).
