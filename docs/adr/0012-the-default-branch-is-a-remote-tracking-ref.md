# The default branch is a remote-tracking ref

> **Retired.** This record is kept for its history. Its product intent now lives in
> [product.md](../product.md) and its implementation detail in
> [default-branch.md](../spec/default-branch.md). Nothing below is maintained.

A Repo's default branch resolves to a remote-tracking ref, never a local branch: an explicit per-Repo override from config (shape owned by the "Design the config schema" ticket), then `refs/remotes/<remote>/HEAD` read through the git common dir with its symbolic target validated to exist, then a name list over remote-tracking refs only (`origin/main`, `origin/master`, `origin/trunk`), then Unknown. The remote is gix's fetch-default: `origin` when present, the sole remote when there is exactly one, nothing when there are two or more and none is called `origin`; for a fork `origin` is right, because the user's branches merge into their own fork's default. `init.defaultBranch` is rejected as a source (it records what the machine that ran `git init` was configured with and says nothing about a clone), and `remote.origin.HEAD` is not a git config key at all.

Remote-tracking wins over local `refs/heads/main` on an asymmetry: a local branch goes stale without bound and only the user pulling fixes it, so a branch that landed three weeks ago reads as unlanded and never self-corrects, while a remote-tracking ref goes stale only until the next fetch, which Repon controls. A tool whose pitch is the truth about many Repos without the user touching them cannot rest on a ref whose accuracy depends on the user having touched them. It also survives Worktrees: 163 of 409 measured entities are linked Worktrees, many with no local default branch checked out at all. Mechanics live in [the default branch spec](../spec/default-branch.md).

`git symbolic-ref` returns a stale target with exit 0, and gix's `target()` does the same, because neither checks that the branch it names still exists; of the tools surveyed (git itself, git-town, gh, lazygit, jj, git-branchless, GitButler, magit, VS Code, Sapling, gitui) only GitButler validates, so Repon validates. Validation only catches the dangling case, though, and a read-only sweep of 220 distinct git common dirs (each cached `origin/HEAD` against the remote's advertised HEAD via `git ls-remote --symref`) found none: 193 agreed, 7 were wrong, 3 remotes were unreachable, and every wrong one was stale-but-resolvable, which nothing local can detect from the ref alone. Coverage is near-total (`origin/HEAD` exists on 349 of 366 non-fixture entities and 163 of 163 linked Worktrees; the 17 without it have no remote, so no upstream, no ancestry and no state to be wrong about), and reading it in-process across the whole population costs about 20ms against about 4 seconds shelling out, of which roughly 99% is git startup. So the name list earns its place by disagreeing with `origin/HEAD` on Repos that have one, the only local detector for the stale case; the wrong dotfiles Repo (cached `master`, truth `main`) is caught this way. The disagreement is recorded on the Repo and surfaced in the detail pane, and `origin/HEAD` still wins the precedence. The other 6 wrong entities mark the ceiling: `qmk_firmware` Submodules cached as `master` when the truth is `qmk-master`, where the name list picks the same wrong answer and no local signal exists (they are hidden by default under [0009](0009-worktree-state-model.md)). Only the remote knows that answer, so it is asked at fetch time: the handshake already advertises HEAD, so the remote's answer arrives in a round trip already being paid for, supersedes the local ref for the session, and is held in memory only, never written back to `refs/remotes/<remote>/HEAD`, which keeps the core read-only and [0006](0006-no-git-state-cache-session-state-by-name.md) intact. An explicit user-triggered re-derive over the Selection does the same on demand.

This amends Merged ([0009](0009-worktree-state-model.md)). A squash-merged branch is never an ancestor of the default branch, so on a Repo that squash-merges everything, ancestry-defined Merged is dead and every landed branch arrives as Gone. Merged becomes "the branch's work has landed in the default branch, by ancestry or by patch equivalence": ancestry is checked first and wins, and where it says no, a content proof runs as a second pass. This sharpens both states. Merged means the work landed; Gone means the upstream vanished and the work could not be shown to have landed, which is precisely when to look before sweeping, where today Gone is a mixed bag of squash merges and abandoned PRs. The content proof costs roughly 130ms per branch against about 20ms for ancestry, so it runs as a separate pass and the state cell stays blank and Loading until it answers; showing Gone and flipping to Merged two seconds later is a screen contradicting itself, the defect [0001](0001-per-cell-provenance.md) exists to prevent. It also must not write to the object database, so the common `git commit-tree` trick is out and the patch-id comes from an in-memory diff.

## Consequences

- Two behind numbers exist and both are shown: behind the upstream (a collaboration signal, someone pushed to my branch) in the `sync` column, and behind the default branch (an integration signal, trunk moved under me) in a new `base` column. They coincide only when a branch's upstream is the default branch, which corrects the ticket's framing of them as one number.
- A future reader will want the network probe (gix's `ref_map` with an extra `HEAD` refspec, no fetch needed) as the primary source, since it is the only source that is always right. It cannot be: 3 of 220 remotes were unreachable, and the render path budget is about 20ms for the whole population, not a round trip per Repo.
- A future reader will also want to write the corrected answer back with the equivalent of `git remote set-head`. That is a mutation, and the core does not write.
- When nothing resolves, the state is Unknown (gutter `?`), not Failed. No default branch determinable is a settled answer; Failed stays reserved for a git error ([0010](0010-provenance-renders-as-a-row-gutter-and-blank-cells.md)).
- A default branch derived from the name list is marked in the detail pane and nowhere in the list, because in the measured population that path fires only on Repos with no remote, which show no upstream, no ancestry and no state to mislead anyone about.
- Since git 2.48 a plain fetch with default refspecs creates a missing `origin/HEAD`, and `remote.origin.followRemoteHEAD=always` corrects a stale one, so a periodic fetch that shells out to git improves the local ref for free. Input to the "Decide the refresh model" ticket, along with pruning: Gone only appears after a prune, so if Repon fetches it must prune, and if it does not fetch, Gone is under-reported.
