# An unbuilt binding is not advertised and an unavailable one answers on press

Two conditions look identical from the keyboard and are opposites. A binding is **Built** or not, which is static, decided at compile time, and decides whether the binding is offered at all: an unbuilt binding is absent from the footer and the help overlay, does not dispatch, and says nothing, because it was never offered. A Built binding is **Available** or not, which is dynamic, decided per keystroke against the current state, and decides only whether it acts: an unavailable binding stays advertised exactly as it was and answers the press with a **Notice** naming why it did nothing. The whole decision is which side of the keystroke the answer falls on. For an unbuilt binding it falls before, by never making the offer; for an unavailable one it falls after, because the offer was real and is momentarily refused.

The unbuilt half is [0001](0001-per-cell-provenance.md)'s founding rule one plane up. An absent count must never render as a zero, and an advertised key that does nothing is the same lie told about the program rather than about a Repo: the footer is a claim about what Repon does, and three of the seven hints in its 88-column list footer were false when this was decided, `/ filter` ([#63](https://github.com/paulchiu/repon/issues/63)), `! launcher` ([#98](https://github.com/paulchiu/repon/issues/98)) and `r refresh` ([#65](https://github.com/paulchiu/repon/issues/65)), while `; action` became true when the Action palette landed. So the answer is not a better message but no offer: an unbuilt action keeps its chord reserved in the table, where the load-time collision check and the debug-build assertion over the default map still see it, and the surfaces filter on `built` instead. [0016](0016-one-binding-table-feeds-every-surface.md) is untouched by that, because filtering is a projection of the one table in exactly the way the footer's width-driven drops already are, and the table stays the single source every surface derives from. The alternative, dropping the chord entirely, was refused because it silently gives up the reservations this map paid a whole ticket to decide: `!`, `;`, `/` and `1` to `9` would be free, and nothing at load or in review would fire when a later feature took one.

The mechanism this replaces failed in a way worth recording, because it failed by being reasonable. [#97](https://github.com/paulchiu/repon/issues/97) added a fourth `Warning` variant, `NotImplemented`, reusing the shared warning slot rather than inventing a surface, and ranked it lowest on the sound grounds that a key you just pressed puts nothing already on screen in doubt. Both halves of that then bit. The notice was never cleared, only replaced by the next such press, so a `r` at 09:00 still read "Refresh everything is not implemented yet" at 17:00. And ranking lowest against a slot that shows only the most severe condition made it invisible at the moment it fired: with one unknown config key outstanding, pressing `/` moved the screen from `unknown config key \`x\`` to `unknown config key \`x\` (+1 more, w to expand)`, so the feedback the feature existed to give was a digit ticking in a suffix. Those are not implementation defects to fix in place. They are what happens when a reply to a keystroke is ranked against standing conditions, which is the distinction the rest of this decision rests on.

The available half already ships, unnamed and mute. [keybindings.md](../spec/keybindings.md) makes `;`, `s`, `1` to `9` and `Ctrl+R` inert while an Action is fanning out, because a second Action, a Set switch and a config reload each invalidate the run underneath itself; [0018](0018-an-action-is-a-fanout-of-pty-backed-steps.md) prices that as a binding conditional on runtime state rather than on context. Those four are advertised, pressed and silent today, which is the same defect [#97](https://github.com/paulchiu/repon/issues/97) was filed about arriving by a different road. The population grows with every feature: `n` and `N` with no failed rows, `d` with nothing Vanished, `;` with a Selection no Repo defines an Action for. Unlike the unbuilt population, it never reaches zero, which is what makes the Notice worth building at all; designing a permanent surface for a temporary condition is what this decision refuses, and the temporary condition is answered by silence instead.

The answer lands after the press rather than before it for three reasons. The footer is a teaching surface and a teaching surface has to hold still: marking an unavailable binding would rewrite the footer as the cursor moved between a failed row and a clean one, and [keybindings.md](../spec/keybindings.md)'s rules 2 and 3 are entirely about which reach the footer teaches, which a footer that changes under the eye cannot do. The budget refuses it independently, the list footer being 87 columns of an 88-column narrow screen with no room for a per-item mark, and [0011](0011-themes-correct-the-terminal-palette.md) forbids meaning carried by colour alone, so dimming is not available on its own and a mark costs a glyph. And the reason is usually a sentence rather than a state: "none of the 4 selected Repos define this Action" is the single most useful thing Repon can say at that moment and there is no glyph for it. This is lazygit's disabled reason, which [keybindings.md](../spec/keybindings.md) already cites for the opposite purpose, as the one place lazygit is not followed.

The Notice takes over the status row, ahead of the warning slot and ahead of the header, and it is the only thing on screen whose content the user caused, which is why it outranks two things that are both still true when it goes. Making it an item in the header's drop table was refused by that table's own arithmetic: [actions.md](../spec/actions.md) measures the header at 85 columns of an 88-column narrow screen with nothing in flight and 107 with run progress, so a Notice added as an item either drops or drops everything below it, and a reply to a keystroke being the first casualty at the width where the user can least go and check is the failure rule 3 of the footer already names. The footer row was refused because it destroys the teaching surface at precisely the moment the user is confused about a key, which is the failure [keybindings.md](../spec/keybindings.md) records lazygit committing when its `?` filters out of popup footers. A dedicated row was refused for spending a permanent line on a surface that is empty almost always, and making that row appear only when occupied moves every row under the cursor for three seconds.

So the warning slot carries **standing conditions of the session only**, and that is now a rule rather than an accident of what happened to be in it. A theme that half-applied, a config key that fell back and an abandoned discovery are each continuously true until something changes them, each dismissible, each putting something already on screen in doubt; a keystroke's reply is none of those. `Warning::NotImplemented` is deleted and the slot returns to the three sources [config.md](../spec/config.md) amended [theming.md](../spec/theming.md) into. A Notice never enters that slot, never appears in `w`'s expanded list, and never reaches `repon.log`, because [theming.md](../spec/theming.md)'s report-twice rule is about warnings and a Notice is not one. The rule reaches past this ticket: it is also why a failed Action's receipt stays in the row and the detail pane where [actions.md](../spec/actions.md) put it.

A Notice is cleared by its timeout, by a replacement, or by the next keypress, whichever comes first. The timeout defaults to three seconds and is configurable as `notice_timeout`, which is a deliberate divergence from [actions.md](../spec/actions.md), where a configurable expiry was dropped, and the distinction is that a receipt's "until the next run" was a lifetime that satisfied the requirement exactly, while three seconds is a reading-speed preference and reading speed is the user's. `"0s"` means the timer is off, not that Notices are off, which is the literal reading of the poll's own `"0s"` (the timer does not run) and which recovers "cleared by the next keypress" as a setting rather than losing it. There is no key that disables Notices, because that would put [#97](https://github.com/paulchiu/repon/issues/97)'s defect one config line away. The render loop already runs continuously, so the timeout costs no new machinery, and tests drive the clock rather than the wall.

The Notice takes the `text` role, plain, against the status row's `dim`, so it is the brightest thing on the row through contrast that already exists. `warn` was refused because painting a refusal the same colour as a Dirty Worktree and a half-applied theme would undo the separation this decision just drew, and a tenth role was refused because one message does not earn one; [theming.md](../spec/theming.md) states the nine explicitly so a tenth is added deliberately rather than discovered. [0011](0011-themes-correct-the-terminal-palette.md) is satisfied either way, since the words carry the meaning and the role only points at it.

The reason is computed at the point of refusal rather than fixed per action, because `;` refusing for "no Actions are configured" and `;` refusing for "none of the 4 selected Repos define this Action" are different facts and the second is the useful one; a fixed string per action is exactly what a footer mark could already have carried, so choosing it would make the after-the-press answer pointless. Each reason's static text is authored to fit 44 columns, half the 88-column narrow screen, and that budget is asserted by a test rather than enforced by truncating at render, because `Buffer::set_stringn` truncates silently at a grapheme boundary and a half-rendered sentence is worse than the half-rendered footer hint the same fact already ruled out. This is the same instinct as [0020](0020-the-ascii-glyph-set-is-vetted-over-the-row-interior.md)'s compile-time disjointness assertion: a rule that can be checked before a user sees it, is.

[keybindings.md](../spec/keybindings.md) stays consistent with the program by naming the bindings that are not Built, in one list rather than a column across six tables, checked by the `spec_conformance` test that already reads that document. A column would be six columns of "yes" concealing eleven "no"s and would grow the spec's tables permanently to record something temporary; the list reads as the exception set it is and shrinks to nothing. A generated block was refused for putting machine text inside a hand-written spec and gaining nothing over a checked list. Marking nothing at all was refused on the user's own requirement that the documentation stay consistent throughout, and on [0021](0021-a-release-is-what-the-tag-pipeline-publishes.md)'s recorded evidence of what an unchecked hand-maintained fact does over time.

A user binding an unbuilt action in config, `[keys.list] filter = "F5"`, warns, names the dotted path and continues, with the binding ignored. It is not an unknown action, since the name is in the enum, in `keys::description` and in the spec, so the message says not built yet rather than unknown, or the user goes looking for a typo that is not there. Exiting was refused as disproportionate: the config is not wrong, it is early, and it becomes correct with no edit on the day the feature lands, which is the reason the name stays accepted vocabulary. Accepting it silently was refused because it rebuilds this decision's whole defect by hand, through the one door left open.

One question is left open and ticketed rather than settled here. [theming.md](../spec/theming.md) puts the warning slot in the status bar and [actions.md](../spec/actions.md) gives the header a five-item drop table for the same row, and neither document mentions the other; today it does not bite only because the header is not built and the slot paints the whole row. Ranking a persistent warning above the header hides the entity count for a whole session, and ranking it below drops a warning silently at 88 columns, which is the quiet lie [theming.md](../spec/theming.md) invokes [0001](0001-per-cell-provenance.md) to forbid. It bites with no keypress and no Notice involved, so it is not this decision's to make, and this decision holds either way because the Notice sits above both.
