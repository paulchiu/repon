# One binding table feeds every surface, and a collision is a load error

Repon's keybindings are user-configurable through a `[keys]` block in config.toml, and the compiled-in default map is a single table in code. Three surfaces read that one table rather than restating it: the always-visible contextual footer, the help overlay and the config merge. Two actions bound to the same key within one context is a load error rather than a footer that quietly disagrees with the keyboard.

The obvious implementation is a hardcoded footer string per pane, and it is correct exactly until someone rebinds a key, at which point the screen is telling the user to press something that does nothing. Repon's reload-config keystroke makes that a per-session lie rather than a per-install one, because the keyboard can change under the user mid-session. lazygit and gitui both derive their footers from their binding tables, so this is the settled practice rather than a novel idea. It is still a decision worth recording: every surface reading the table makes it hard to reverse, and the trade-off is real, because a derived footer costs a width-budgeting pass on every frame that a literal string does not. Mechanics live in [the keybinding spec](../spec/keybindings.md).

Deriving is where the bugs actually live, and lazygit has two worth not copying. Its footer budget check at pkg/gui/options_map.go:121 reads `if i > 0 && length+len(separator)+textLen > width`: the `i > 0` guard appends the first item with no width test at all, so a single long item overruns the pane by an unbounded amount, and if a later item then triggers the ellipsis branch the result is wider than the pane it sits in. Repon width-checks every item including the first, and reserves the ellipsis inside the budget rather than adding it afterwards. The second defect is about which binding survives. lazygit's `?` help binding is not pinned: pkg/gui/controllers/global_controller.go:93 attaches a GetDisabledReason, and optionsMenuDisabledReason (same file, lines 220 to 229) returns an empty-text disabled reason whenever the context is a popup, which the disabled-binding filter then removes from the options map. So the escape hatch disappears from the footer in exactly the contexts where a user is most lost. Repon pins `?` in every context except the input contexts, where every printable character has to be typeable and the footer already carries the three bindings a user goes looking for.

Nothing underneath does the dropping for you. ratatui-core 0.1.2's `Buffer::set_stringn` (src/buffer/buffer.rs:336) truncates silently at a grapheme boundary, through a `map_while` over `remaining_width.checked_sub(width)?`. It does not wrap and it does not panic. Left alone it cuts a binding in half, which is worse than dropping it, because a half-rendered hint still reads as an instruction. Widths come from unicode-width 0.2.2, and every glyph in Repon's value set measures 1 there while measuring 2 under `width_cjk`, which is why the footer is written in ASCII words rather than symbols. The list context's footer is 87 columns at full width, which fits inside both the 90-column list and the 88-column narrow screen the layout prototype ran at, so it degrades only on genuinely small frames:

```
 88  j/k move  space select  enter detail  / filter  ! launcher  ; action  r refresh  ? help
 80  j/k move  space select  enter detail  / filter  ! launcher  ; action  ? help ...
 70  space select  enter detail  / filter  ! launcher  ; action  ? help ...
 60  space select  / filter  ! launcher  ; action  ? help ...
 50  space select  ! launcher  ; action  ? help ...
 40  ! launcher  ; action  ? help ...
 30  ? help ...
  6  ? help
```

Two rules govern that table. A hint drops earlier when its action has a second binding the user would guess anyway, which is why `r refresh` goes first (focus-gain and the poll already refresh without it) and `j/k move` second (the arrow keys are bound too). And `! launcher` and `; action` drop as one atomic pair, never separately, because a footer advertising the one-Repo key while hiding the N-Repo key teaches the wrong reach at exactly the width where the user can least go and check. That is [0008](0008-two-palettes-not-one.md)'s safety boundary expressed in the footer rather than only in the keys.

The collision rule sits in deliberate contrast with [0011](0011-themes-correct-the-terminal-palette.md). Theming refused to make glyphs themeable because ADR 0010's disjointness is a correctness property and no flat TOML schema can express "these two sets must not intersect" to someone editing the file. A key collision is the same class of property, with one difference that changes the answer: it can be checked at load. So it is checked rather than forbidden. Two actions on one key in one context exits non-zero before the terminal is claimed, the same grade [config.md](../spec/config.md) already gives a bad value in a known key, because the alternative is a keyboard that silently does the wrong thing. The merge is keyed on the action name rather than the key, so a user writes `[keys.list] refresh = "F5"` to move one binding and leaves the rest of the default map alone, and binding an action to the empty string unbinds it.

The space the default map had to fit into is narrower than it looks, and the constraints are measured rather than recalled. crossterm 0.29.0's src/event/sys/unix/parse.rs matches `\r` to Enter at line 92 and `\t` to Tab at line 102, both before the `\x01..=\x1A` control-byte arm at line 106, so those two chords never carry a CONTROL modifier; `\n` in raw mode falls through to that arm and arrives as Ctrl+J, which the source comments on directly; `\x7F` is Backspace and `\x08` is Ctrl+H, so the two are distinct on macOS; and `char_code_to_event` adds SHIFT to any uppercase character, so a match arm for `Char('R')` must carry the modifier or it never fires. Above that, the terminal decides which bytes it sends, and they disagree. Ghostty 1.3.1 deliberately excludes `i`, `m` and `[` from its C0 table per the fixterms specification and emits CSI u sequences instead, even with the kitty keyboard protocol off, while iTerm2, Alacritty, WezTerm and Terminal.app emit the C0 bytes. crossterm reaches its CSI u parser unconditionally at parse.rs:203, with no feature gate, so Ctrl+I, Ctrl+M and Ctrl+[ arrive as `Char` plus CONTROL on one terminal and as Tab, Enter and Esc on the others. They are not unbindable because they are impossible; they are unbindable because they mean different things in different places.

Raw mode is `cfmakeraw`, and a C probe compiled against Apple's libc on the design machine confirms it clears IXON, IXOFF, ISIG, ICANON, IEXTEN, ECHO and OPOST. So Ctrl+S and Ctrl+Q are not eaten by software flow control, and Ctrl+C and Ctrl+Z arrive as key events rather than signals, which means quit and suspend are Repon's to implement rather than the kernel's to provide. Past the terminal driver, the question is who claims a chord before Repon sees it. Ghostty claims no Ctrl+letter chord of its own: verified locally at 1.3.1, 93 default bindings, of which the only bare Ctrl chords are ctrl+tab and ctrl+shift+tab. The multiplexer takes the largest bite. zellij 0.45.0's default configuration binds Ctrl+g, q, p, n, s, o, t, h and b, plus 18 distinct Alt chords, before a running program sees them, and tmux takes Ctrl+b. That leaves Ctrl+a, c, d, e, f, j, k, l, r, u, v, w, x, y and z, and macOS itself claims Ctrl+F1 through Ctrl+F8 and the Ctrl+arrow chords. Every Ctrl binding in the default map sits inside that surviving set.

Two more constraints are keyboard decisions rather than footnotes. Bracketed paste is enabled, because the ad hoc command field accepts multiple lines: without it a pasted two-line command arrives as Enter, then Ctrl+J, then whatever else, so it submits itself halfway through, and with it the whole paste arrives as one event. Mouse capture is not enabled at all, because it takes the terminal's own select-and-copy away, and Repon's screen is mostly Repo paths and branch names that people copy out of it. That is a deliberate no for now rather than a closed door, and the condition for reopening it is someone wanting to try it.

## Amended by 0018

The table is no longer a pure function of context. While an Action is fanning out, `;`, `s`, `1` to `9` and `Ctrl+R` are inert, because a second Action, a Set switch that re-runs discovery and a config reload that can delete the running entry each invalidate the run underneath itself. The footer is derived and follows for free, but the help overlay and the load time collision check are both over the static table and now describe keys that a moment of runtime state can disable. This ADR rejected lazygit's `GetDisabledReason` for making the escape hatch vanish where a user is most lost, and the narrower version taken here is four keys in one state rather than a general mechanism. See [0018](0018-an-action-is-a-fanout-of-pty-backed-steps.md).

## Consequences

- The footer and the help overlay contain no literal binding strings; both render from the table and are tested against it, so neither can drift from what the keys do.
- A rebind through `[keys]` changes the footer and the help overlay with no code change, including after a mid-session config reload.
- The width-budget pass runs on every frame, must width-check the first item and must reserve the ellipsis inside the budget; that is the per-frame cost a literal string would not pay.
- `?` is pinned in every context except the input contexts, so the escape hatch never vanishes from the footer where a user is most lost.
- A future reader will want to hardcode the footer for speed; the per-frame pass is the price of a footer that never lies, and buying it back reintroduces the lie.
- The collision check runs over the default map itself at startup, not only over user config, because the default map can grow a collision in review as easily as a config file can.
- Ctrl+I, Ctrl+M and Ctrl+[ are permanently unavailable, and a future reader who tests only on Ghostty will conclude otherwise; everywhere else they arrive as Tab, Enter and Esc.
- Quit and suspend are implemented rather than inherited: raw mode delivers Ctrl+C and Ctrl+Z as key events, so Repon handles them or nothing does.
- Mouse support is a deliberate no with a named reopening condition, someone wanting to try it, because capture takes the terminal's select-and-copy away from a screen full of copyable paths.
- The `[keys]` schema is keyed on action names, so renaming an action is a breaking config change and carries the same weight as removing a key from config.toml.
