# One binding table feeds every surface, and a collision is a load error

Repon's keybindings are user-configurable through a `[keys]` block, and the compiled-in default map is a single table in code. Three surfaces read that one table rather than restating it: the contextual footer, the help overlay and the config merge. No surface may carry a literal binding string. A hardcoded footer is correct exactly until someone rebinds a key, and Repon's reload-config keystroke makes that a per-session lie rather than a per-install one, because the keyboard can change under the user mid-session.

Two actions bound to the same key within one context is a load error: Repon exits non-zero before the terminal is claimed rather than showing a footer that quietly disagrees with the keyboard. The check runs over the compiled default map as well as over user config, because review can grow a collision as easily as a config file can. The merge is keyed on the action name, so a rebind moves one binding and leaves the rest of the map alone.

The footer drops hints to a budget rather than truncating them, width-checks every item including the first, and reserves the ellipsis inside the budget. The Launcher and Action hints drop as one atomic pair, never separately, because a footer advertising the one-Repo key while hiding the N-Repo key teaches the wrong reach: [0008](0008-two-palettes-not-one.md)'s safety boundary expressed in the footer.

**Enforcement:** `a_keys_collision_exits_before_the_terminal_is_claimed_naming_both_actions_and_the_key` in `crates/repon/tests/terminal_restoration.rs`, over a real pty. `find_collisions` and `debug_assert_compiled_default_has_no_collision` in `crates/repon/src/keys.rs` are the check itself, with `no_key_literal_is_written_outside_this_table` beside them. In `crates/repon/src/footer.rs`, `list_footer_matches_the_documented_degradation_table_at_every_named_width` parses the spec's own drop table and compares it to the real budget, and `launcher_and_action_hints_are_never_present_without_each_other_at_any_width`, `budget_width_checks_the_first_item_not_only_later_ones` and `footer_never_calls_the_silently_truncating_set_stringn_helper` hold the rest.
